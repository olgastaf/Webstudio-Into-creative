# Установка обновлённой формы

Комплект подготовлен под предоставленный component.php и текущий серверный обработчик с ddv-e.ru. Файл ядра component.php менять не нужно.

## Что изменено

- Таблицы заменены блоками div; для группы радиокнопок используется fieldset.
- Плавающие label связаны с input через id и for.
- Порядок: тип клиента → ИНН → кнопка заполнения → КПП → адрес → наименование → фамилия → имя → отчество → email → телефон → пароль → согласие → кнопка.
- Отчество необязательно; фамилия, имя, email и телефон обязательны.
- Вводится один пароль. CONFIRM_PASSWORD формируется на сервере до вызова компонента.
- LOGIN формируется из EMAIL до вызова компонента и дополнительно проверяется в обработчике.
- Пароль не возвращается в HTML после ошибки.
- POST выполняет обычную перезагрузку страницы. После неё окно открывается автоматически для ошибки, результата регистрации или SMS-кода.
- Автоматический переход отключён: USE_BACKURL=N, SUCCESS_PAGE пустой. Перейти в кабинет можно по кнопке после авторизации.
- Сообщение успешной регистрации определяется по VALUES[USER_ID], а не только по статусу входа.
- При подтверждении email показывается сообщение о письме, повторная форма не выводится.
- Кнопка «Заполнить по ИНН» пока отключена. DaData не подключена.
- Серверная проверка согласия и назначение бизнес-группы 8 сохранены. Добавлена проверка сессии.
- JavaScript модального окна больше не зависит от jQuery; включены Escape, возврат фокуса и удержание Tab внутри окна.

## 1. Шаблон

Сохраните текущую рабочую версию перед заменой.

В папке сайта:

/local/templates/ИМЯ_ШАБЛОНА/components/bitrix/main.register/individual-business-reg/

замените три файла из individual-business-reg:

- template.php
- script.js
- style.css

Остальные файлы шаблона, включая lang и images, не удаляйте.

## 2. Подключение

Замените прежний фрагмент модального окна и вызов main.register содержимым index.php.

index.php из комплекта — фрагмент, а не полноценная страница: не заменяйте им целиком файл страницы с подключением header.php и footer.php. Сохраните пролог, эпилог и другой контент сайта.

Уберите прежний inline-скрипт модального окна и прежние inline-стили .register-modal. Новые стили и скрипт находятся в шаблоне компонента и подключаются Битриксом.

Подготовка LOGIN и CONFIRM_PASSWORD должна выполняться перед IncludeComponent. Одного изменения шаблона недостаточно: стандартный компонент проверяет эти поля до событий создания пользователя.

Если этот фрагмент выполняется в другом месте сайта, перенесите весь блок подготовки данных вместе с вызовом компонента.

Адрес кнопки личного кабинета /personal/ можно изменить в template.php.

## 3. Обработчик

Замените на сайте:

/local/php_interface/include/individual_business_reg.php

файлом php_interface/include/individual_business_reg.php из комплекта.

В комплекте init.php содержит прежнее подключение. Если на сайте уже добавлены другие обработчики, не перезаписывайте весь init.php: проверьте только строку подключения этого файла.

На другом сайте измените $businessGroupId = 8 на фактический ID бизнес-группы.

Все PHP-файлы сохраняйте в UTF-8 без BOM.

## 4. Проверка

После обновления очистите кеш страницы/компонента и обновите страницу браузера с перезагрузкой ресурсов.

Проверьте на новых тестовых email:

1. Частное лицо: бизнес-поля скрыты и не отправляются.
2. Организация: ИНН 10 цифр, КПП 9 цифр, адрес и название обязательны.
3. ИП: ИНН 12 цифр, КПП необязателен и очищается на сервере.
4. После ошибки окно открыто, выбор типа и реквизиты сохранены. Пароль нужно ввести снова.
5. Без согласия браузер блокирует отправку; сервер также проверяет согласие.
6. После успеха окно открыто с сообщением. Если включено подтверждение email, отображается инструкция о письме.
7. LOGIN нового пользователя равен email; отдельного поля логина нет.
8. Бизнес-пользователь получает группу 8; частное лицо её не получает.
9. На телефоне поля не выходят за ширину окна, окно прокручивается.
10. Закрытие по фону, крестику и Escape работает.

Телефон хранится в PERSONAL_PHONE. Если на сайте включена обязательная авторизация по телефону, номер также передаётся в PHONE_NUMBER, а шаблон сохраняет ввод SMS-кода. Этот дополнительный сценарий требует отдельной проверки на сайте.

## Ограничения

- Контрольные цифры ИНН и существование компании не проверяются.
- Согласие проверяется, но запись в журнале согласий Битрикса пока не создаётся.
- Этот шаблон предназначен для согласованного набора полей. Дополнительные обязательные UF-поля потребуют включения в разметку.
- Это обновление регистрации; авторизация ещё не добавлена.
- Синтаксис JavaScript проверен локально. PHP и интеграция с Битриксом требуют проверки на сайте: локально PHP и сервер Битрикса недоступны.

Цвет кнопок и фокуса меняется в style.css через --registration-accent.
