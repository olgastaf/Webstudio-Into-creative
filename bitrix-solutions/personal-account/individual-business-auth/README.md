# Регистрация и авторизация частных лиц и организаций / ИП

Решение разрабатывается для сайта ddv-e.ru.
Некоторые сценарии интерфейса взяты за ориентир с ekf.market.

**Статус:** регистрация реализована и проверена на ddv-e.ru.
Авторизация и автозаполнение реквизитов по ИНН — следующие этапы разработки.

## Возможности

- Регистрация в модальном окне.
- Выбор типа клиента двумя радиокнопками.
- Показ реквизитов только для организаций / ИП.
- Проверка обязательных реквизитов на сервере.
- Назначение дополнительной группы организациям / ИП.
- Сохранение выбранного типа клиента после ошибки.
- Открытие модального окна после ошибки регистрации.

## Структура решения

- `index.php` — пример подключения компонента, разметка модального окна, его стили и скрипт.
- `individual-business-reg/` — шаблон компонента `bitrix:main.register`.
- `individual-business-reg/template.php` — разметка регистрации.
- `individual-business-reg/script.js` — переключение полей по типу клиента.
- `php_interface/init.php` — пример подключения серверного обработчика.
- `php_interface/include/individual_business_reg.php` — проверка данных и назначение группы.

## Инструкция по установке и настройке

### 1. Создание пользовательских полей

Создайте поля для сущности «Пользователь»:

| Код поля | Назначение | Тип |
|---|---|---|
| UF_CLIENT_TYPE | Частное лицо или организация / ИП | Список |
| UF_INN | ИНН | Строка |
| UF_KPP | КПП | Строка |
| UF_BUSINESS_ADDRESS | Адрес организации / ИП | Строка |

Все поля должны быть одиночными, не множественными.

Не включайте обязательность этих полей в их настройках.
Обязательность для данной формы проверяет серверный обработчик.

ИНН и КПП хранятся как строки, чтобы сохранять начальные нули.

Для поля `UF_CLIENT_TYPE` создайте значения:

| XML_ID | Значение |
|---|---|
| individual | Я частное лицо |
| business | Я являюсь представителем юридического лица или индивидуального предпринимателя |

Установите «Я частное лицо» значением по умолчанию.

XML_ID должны точно соответствовать таблице.
Числовые ID вариантов определяются кодом автоматически.

Для названия организации / ИП используется стандартное поле
`WORK_COMPANY`. Дополнительное пользовательское поле не требуется.

### 2. Настройка групп пользователей

Используется существующая группа «Зарегистрированные пользователи».

В настройках Главного модуля проверьте, что она включена в список
групп новых пользователей при регистрации.

Создайте дополнительную группу «Юридические лица и ИП».
Не включайте для неё автоматическое добавление всех новых пользователей.

| Тип клиента | Группы после регистрации |
|---|---|
| Частное лицо | Стандартные группы новых пользователей |
| Организация / ИП | Стандартные группы + «Юридические лица и ИП» |

На ddv-e.ru ID дополнительной группы — `8`.

На другом сайте укажите её фактический ID в обработчике:

```php
$businessGroupId = 8;
```

Назначайте группе права и условия, предназначенные для пользователей,
которые самостоятельно выбирают бизнес-регистрацию.
Этот выбор не подтверждает полномочия представителя организации.

### 3. Установка шаблона регистрации

Скопируйте папку `individual-business-reg` в:

```text
/local/templates/ИМЯ_ШАБЛОНА/components/bitrix/main.register/
```

Итоговый путь к шаблону:

```text
/local/templates/ИМЯ_ШАБЛОНА/components/bitrix/main.register/individual-business-reg/
```

Сохраните остальные файлы шаблона, включая языковые файлы и стили,
если они присутствуют.

Используйте собственный шаблон компонента, не изменяя файлы ядра Битрикса.

### 4. Подключение компонента и модального окна

Файл `index.php` содержит пример для вставки в страницу сайта
или подходящее место его шаблона. Он не является самостоятельной
страницей с подключением пролога и эпилога Битрикса.

Скрипт модального окна использует jQuery.
Библиотека должна быть подключена до выполнения этого скрипта.

Перед вызовом компонента установите признак нашей регистрации:

```php
if (!defined('INDIVIDUAL_BUSINESS_REGISTRATION')) {
    define('INDIVIDUAL_BUSINESS_REGISTRATION', true);
}
```

Основные параметры компонента:

```php
$APPLICATION->IncludeComponent(
    "bitrix:main.register",
    "individual-business-reg",
    [
        "SHOW_FIELDS" => [
            "EMAIL",
            "NAME",
            "LAST_NAME",
            "PERSONAL_PHONE",
            "WORK_COMPANY",
        ],
        "USER_PROPERTY" => [
            "UF_CLIENT_TYPE",
            "UF_INN",
            "UF_KPP",
            "UF_BUSINESS_ADDRESS",
        ],
        "REQUIRED_FIELDS" => [
            "EMAIL",
            "NAME",
            "PERSONAL_PHONE",
        ],
        "AUTH" => "Y",
        "USE_BACKURL" => "Y",
        "SUCCESS_PAGE" => "/personal/",
        "SET_TITLE" => "N",
    ],
    false
);
```

Пользовательские поля указываются в `USER_PROPERTY`,
стандартные поля — в `SHOW_FIELDS`.

Не добавляйте `WORK_COMPANY` в `REQUIRED_FIELDS`:
название требуется только для организации / ИП.

Настройте `SUCCESS_PAGE` под адрес личного кабинета на вашем сайте.
При включённом `USE_BACKURL` переход может определяться параметром
`backurl`. Подтверждение email и телефона зависит от настроек сайта.

### 5. Подключение серверного обработчика

Разместите обработчик по адресу:

```text
/local/php_interface/include/individual_business_reg.php
```

В `/local/php_interface/init.php` добавьте:

```php
<?php

$registrationHandler = __DIR__
    . '/include/individual_business_reg.php';

if (is_file($registrationHandler)) {
    require_once $registrationHandler;
}
```

Если `init.php` уже существует, добавьте подключение к имеющемуся коду,
не заменяя весь файл и не добавляя повторный открывающий тег PHP.

Сохраняйте PHP-файлы в UTF-8 без BOM.
Закрывающий тег `?>` в этих файлах не требуется.

Название файла в подключении должно точно совпадать с фактическим
названием `individual_business_reg.php`.

Проверка `is_file()` пропускает подключение, если файл не найден.
Поэтому после установки обязательно проверьте отказ в регистрации
при пустых реквизитах.

Обработчик зарегистрирован на событии `OnBeforeUserAdd`.
Он ограничен признаком `INDIVIDUAL_BUSINESS_REGISTRATION`
и не применяется в административном разделе.

Признак действует в пределах текущего запроса. Если на той же странице
есть другие способы создания пользователей, проверьте совместимость.

### 6. Правила проверки реквизитов

| Поле | Частное лицо | Организация | ИП |
|---|---|---|---|
| Тип клиента | Обязательно | Обязательно | Обязательно |
| Название | Не требуется | Обязательно | Обязательно |
| ИНН | Не требуется | 10 цифр | 12 цифр |
| КПП | Не требуется | 9 цифр | Не требуется |
| Адрес | Не требуется | Обязательно | Обязательно |

В текущей реализации организация и ИП различаются по длине ИНН.

Для ИП КПП очищается перед сохранением.
Для частного лица реквизиты организации очищаются перед сохранением.

Проверяется формат ИНН и КПП.
Контрольные цифры ИНН, существование организации и достоверность
введённых реквизитов пока не проверяются.

JavaScript скрывает и отключает поля реквизитов для частного лица.
Серверный обработчик выполняет проверку независимо от JavaScript.

### 7. Отображение ошибок в модальном окне

В `template.php` контейнер формы должен содержать признак открытия:

```php
<div
    class="bx-auth-reg"
    data-registration-open="<?=(
        !empty($arResult['ERRORS'])
        || !empty($arResult['SHOW_SMS_FIELD'])
    ) ? 'Y' : 'N'?>"
>
```

В скрипте модального окна после получения `$modal`:

```javascript
const $modal = $('#register-modal');

if ($modal.find('[data-registration-open="Y"]').length) {
    $modal.removeAttr('hidden');
    $('body').css('overflow', 'hidden');
}
```

Это открывает окно после ошибки регистрации или при переходе
к вводу SMS-кода.

## Проверка после установки

Используйте разные тестовые email для успешных регистраций.

Проверьте:

- Две радиокнопки без пустого варианта.
- Выбор частного лица по умолчанию.
- Показ и скрытие реквизитов при переключении.
- Регистрацию частного лица без реквизитов.
- Регистрацию организации с ИНН и КПП.
- Регистрацию ИП с 12-значным ИНН без КПП.
- Отказ при пустых обязательных реквизитах.
- Сохранение выбранного типа и введённых данных после ошибки.
- Отображение ошибки в открытом модальном окне.
- Сохранение пользовательских полей в карточке пользователя.
- Наличие бизнес-группы у организации / ИП.
- Отсутствие бизнес-группы у частного лица.

### Результаты проверки на ddv-e.ru

По результатам ручной проверки подтверждены:

- Регистрация частного лица.
- Регистрация юридического лица.
- Регистрация ИП с 12-значным ИНН и пустым КПП.
- Сохранение заполненных полей.
- Назначение дополнительной группы организациям / ИП.
- Вывод ошибки и отказ в регистрации при пустых реквизитах.
- Переключение отображения полей.

## План дальнейшей разработки

- Авторизация в том же модальном окне.
- Общие стили регистрации и авторизации.
- Восстановление пароля.
- Необязательное автозаполнение реквизитов по ИНН через DaData.
- Дополнительная проверка ИНН.

API-ключи внешних сервисов не следует сохранять в репозитории.
