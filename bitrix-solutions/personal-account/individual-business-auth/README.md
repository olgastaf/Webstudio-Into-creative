# Регистрация и авторизация частных лиц и организаций / ИП

Решение для сайта ddv-e.ru на основе компонентов 1С-Битрикс.
Некоторые сценарии интерфейса взяты за ориентир с ekf.market.

**Статус:** регистрация реализована и проверена на ddv-e.ru.
Авторизация и автозаполнение реквизитов по ИНН — следующие этапы.

## Возможности

- Регистрация в модальном окне.
- Выбор типа клиента: частное лицо или организация / ИП.
- Показ реквизитов только для организации / ИП.
- Плавающие подписи полей.
- Разметка без таблиц.
- Вход в дальнейшем по email: логин формируется автоматически.
- Одно поле пароля.
- Серверная проверка реквизитов, согласия и сессии.
- Назначение дополнительной группы организациям / ИП.
- Автоматическое открытие окна с результатом после отправки.
- Сохранение введённых данных после ошибки, кроме пароля.
- Адаптивные стили, закрытие по крестику, фону и Escape.
- Работа скрипта без jQuery.

## Структура решения

| Файл | Назначение |
|---|---|
| index.php | Пример подключения компонента и разметка модального окна |
| individual-business-reg/template.php | Шаблон формы и сообщений |
| individual-business-reg/style.css | Стили формы и модального окна |
| individual-business-reg/script.js | Переключение полей и управление окном |
| php_interface/init.php | Пример подключения обработчика |
| php_interface/include/individual_business_reg.php | Серверная проверка и назначение группы |
| INSTALL.md | Инструкция по замене файлов и проверке |

Файл `index.php` — фрагмент для страницы с уже подключённым
прологом Битрикса, а не самостоятельная страница.

## Порядок полей

1. Выбор типа клиента.
2. Реквизиты организации / ИП:
   - ИНН;
   - кнопка «Заполнить по ИНН»;
   - КПП;
   - адрес;
   - наименование компании / ИП.
3. Личные данные:
   - фамилия;
   - имя;
   - отчество;
   - email;
   - телефон.
4. Пароль.
5. Согласие на обработку персональных данных.
6. Кнопка регистрации.

Отчество необязательно.

Кнопка «Заполнить по ИНН» пока отключена.
Реквизиты заполняются вручную.

Если в настройках сайта включена CAPTCHA, она также выводится.

## Установка и настройка

### 1. Пользовательские поля

Создайте следующие поля для сущности «Пользователь»:

| Код | Назначение | Тип |
|---|---|---|
| UF_CLIENT_TYPE | Тип клиента | Список |
| UF_INN | ИНН | Строка |
| UF_KPP | КПП | Строка |
| UF_BUSINESS_ADDRESS | Адрес организации / ИП | Строка |

Все поля — одиночные, не множественные.

Не включайте обязательность в настройках этих полей.
Обязательность для данной формы проверяется обработчиком.

ИНН и КПП хранятся как строки, чтобы сохранять начальные нули.

Для `UF_CLIENT_TYPE` создайте значения:

| XML_ID | Значение |
|---|---|
| individual | Я частное лицо |
| business | Я являюсь представителем юридического лица или индивидуального предпринимателя |

Установите «Я частное лицо» значением по умолчанию.

XML_ID должны точно соответствовать таблице.
Числовые ID значений определяются автоматически.

Используются стандартные поля пользователя:

| Поле | Назначение |
|---|---|
| LAST_NAME | Фамилия |
| NAME | Имя |
| SECOND_NAME | Отчество |
| EMAIL | Email |
| PERSONAL_PHONE | Телефон |
| WORK_COMPANY | Наименование компании / ИП |

Создавать дополнительные пользовательские поля для них не нужно.

### 2. Группы пользователей

В настройках Главного модуля проверьте стандартные группы,
назначаемые при регистрации. В них должна входить существующая
группа «Зарегистрированные пользователи».

Создайте дополнительную группу «Юридические лица и ИП».
Не включайте для неё автоматическое добавление всех новых пользователей.

| Тип клиента | Назначаемые группы |
|---|---|
| Частное лицо | Стандартные группы новых пользователей |
| Организация / ИП | Стандартные группы + бизнес-группа |

На ddv-e.ru ID бизнес-группы — `8`.

На другом сайте измените настройку в обработчике:

```php
$businessGroupId = 8;
```

Выбор бизнес-регистрации не подтверждает полномочия представителя
организации. Учитывайте это при назначении прав группе.

### 3. Шаблон компонента

Разместите папку `individual-business-reg` по адресу:

```text
/local/templates/ИМЯ_ШАБЛОНА/components/bitrix/main.register/individual-business-reg/
```

При обновлении замените:

- `template.php`;
- `style.css`;
- `script.js`.

Остальные файлы шаблона, включая `lang` и `images`,
можно сохранить. Файлы ядра Битрикса изменять не нужно.

### 4. Подключение формы

Используйте фрагмент из `index.php`.

Он содержит:

- подготовку логина из email;
- подготовку подтверждения пароля;
- признак нашей регистрации;
- кнопку открытия и модальное окно;
- вызов `bitrix:main.register`.

Подготовка данных должна выполняться **до вызова компонента**:
установленная версия компонента проверяет логин и подтверждение
пароля до событий создания пользователя.

Основные параметры:

```php
[
    'SHOW_FIELDS' => [
        'LAST_NAME',
        'NAME',
        'SECOND_NAME',
        'EMAIL',
        'PERSONAL_PHONE',
        'WORK_COMPANY',
    ],
    'USER_PROPERTY' => [
        'UF_CLIENT_TYPE',
        'UF_INN',
        'UF_KPP',
        'UF_BUSINESS_ADDRESS',
    ],
    'REQUIRED_FIELDS' => [
        'LAST_NAME',
        'NAME',
        'EMAIL',
        'PERSONAL_PHONE',
    ],
    'AUTH' => 'Y',
    'USE_BACKURL' => 'N',
    'SUCCESS_PAGE' => '',
    'SET_TITLE' => 'N',
]
```

Шаблон компонента — `individual-business-reg`.

Не добавляйте `WORK_COMPANY` в `REQUIRED_FIELDS`:
оно обязательно только для организации / ИП.

Автоматическое перенаправление отключено.
После регистрации результат показывается в модальном окне.

Для авторизованного пользователя выводится кнопка перехода
в личный кабинет. Её адрес `/personal/` задаётся в `template.php`.

При замене прежнего подключения удалите старые встроенные стили
и скрипт модального окна. Новые находятся в `style.css` и `script.js`
шаблона компонента. jQuery не требуется.

Не заменяйте целиком страницу сайта фрагментом `index.php`:
сохраните подключение пролога, эпилога и остальной контент.

### 5. Серверный обработчик

Разместите файл:

```text
/local/php_interface/include/individual_business_reg.php
```

В `/local/php_interface/init.php` подключите его:

```php
<?php

$registrationHandler = __DIR__
    . '/include/individual_business_reg.php';

if (is_file($registrationHandler)) {
    require_once $registrationHandler;
}
```

Если `init.php` уже существует, добавьте подключение к имеющемуся
коду, не заменяя весь файл.

PHP-файлы сохраняйте в UTF-8 без BOM.
Закрывающий тег `?>` не требуется.

Имя и путь файла должны точно совпадать с подключением.
Если файл не найден, `is_file()` пропустит подключение без ошибки.
Поэтому обязательно проверьте отказ при пустых реквизитах.

Обработчик использует событие `OnBeforeUserAdd`.

Правила применяются при установленном признаке
`INDIVIDUAL_BUSINESS_REGISTRATION` и не применяются
в административном разделе.

Признак действует в пределах запроса. Если на той же странице
есть другие способы создания пользователей, проверьте совместимость.

## Проверка данных

| Поле | Частное лицо | Организация | ИП |
|---|---|---|---|
| Тип клиента | Обязательно | Обязательно | Обязательно |
| Наименование | Не требуется | Обязательно | Обязательно |
| ИНН | Не требуется | 10 цифр | 12 цифр |
| КПП | Не требуется | 9 цифр | Не требуется |
| Адрес | Не требуется | Обязательно | Обязательно |
| Фамилия и имя | Обязательно | Обязательно | Обязательно |
| Отчество | Необязательно | Необязательно | Необязательно |
| Email и телефон | Обязательно | Обязательно | Обязательно |
| Пароль | Обязательно | Обязательно | Обязательно |
| Согласие | Обязательно | Обязательно | Обязательно |

Организация и ИП различаются по длине ИНН.

Для ИП КПП очищается перед сохранением.
Для частного лица очищаются все реквизиты организации.

JavaScript скрывает и отключает ненужные поля.
Серверная проверка выполняется независимо от JavaScript.

Логин формируется из email на сервере.
Подтверждение пароля формируется из введённого пароля,
отдельное поле не выводится.

Требования к сложности пароля определяются политикой Битрикса.

## Согласие на обработку персональных данных

В форме выводится изначально снятый чекбокс со ссылкой:

```text
/privacy-policy/
```

Без согласия регистрация блокируется браузером и серверным обработчиком.

Запись в штатном журнале согласий Битрикса пока не создаётся.
Подключение `main.userconsent.request` запланировано отдельно.

## Результат отправки

Форма отправляется обычным POST с перезагрузкой страницы.

После отправки модальное окно автоматически открывается:

- при ошибке — с сообщением и заполненной формой;
- после успеха — с сообщением о регистрации;
- при необходимости SMS — с полем кода подтверждения.

После ошибки пароль нужно ввести повторно.

Если включено подтверждение email, после создания пользователя
выводится инструкция о письме для подтверждения регистрации.

Настройки подтверждения email и телефона задаются в Битриксе.

## Проверка после установки

Используйте разные тестовые email для успешных регистраций.

Проверьте:

- Выбор частного лица по умолчанию.
- Переключение типа клиента и отображения реквизитов.
- Регистрацию частного лица без реквизитов.
- Регистрацию организации с ИНН и КПП.
- Регистрацию ИП с 12-значным ИНН без КПП.
- Отказ при пустых обязательных реквизитах.
- Отказ без согласия.
- Сохранение данных после ошибки, кроме пароля.
- Автоматическое открытие окна с ошибкой и результатом.
- Сохранение полей в карточке пользователя.
- Совпадение логина с email.
- Назначение бизнес-группы только организации / ИП.
- Отображение на мобильном экране.
- Закрытие окна по фону, крестику и Escape.

Если используется обязательное SMS-подтверждение телефона,
дополнительно проверьте отправку и ввод кода.

Обновлённая регистрация проверена вручную на ddv-e.ru.
Сценарии с иными настройками подтверждения требуют отдельной проверки.

## Настройка внешнего вида

Основной цвет задаётся в `style.css`:

```css
.registration {
    --registration-accent: #2459b8;
}
```

Тексты подписей, сообщений и адрес личного кабинета
изменяются в `template.php`.

## Ограничения

- Проверяется формат ИНН и КПП, но не существование компании
  и не контрольные цифры ИНН.
- Автозаполнение по ИНН пока не подключено.
- Согласие пока не сохраняется в журнале Битрикса.
- Шаблон рассчитан на описанный набор полей.
  Другие обязательные пользовательские поля потребуют доработки.
- Форма авторизации пока не добавлена.

## Дальнейшая разработка

- Авторизация в том же модальном окне.

- Штатное сохранение согласий.
- Дополнительная проверка ИНН.

API-ключи внешних сервисов не сохраняются в репозитории.
