# Шаблон формы `write_to_us`

Кастомный шаблон компонента `bitrix:form.result.new` для 1С-Битрикс с плавающими `label` (floating label), пользовательским соглашением и стилизованным выводом ошибок.

## Возможности

Шаблон включает:

- floating label для полей формы;
- поддержку обычных `input` и `textarea`;
- сохранение `id`, созданного Bitrix;
- автоматическое добавление `id`, если Bitrix его не сформировал;
- корректную связь `label` с полем через `for`;
- вывод обязательности поля;
- стандартную серверную валидацию Bitrix;
- вывод сообщений об ошибках формы;
- поддержку CAPTCHA Bitrix;
- подключение пользовательского соглашения через `bitrix:main.userconsent.request`;
- отдельный кастомный шаблон соглашения `ic-consent`;
- стилизованный checkbox соглашения;
- стилизованное всплывающее окно с текстом соглашения;
- закрытие окна соглашения по крестику, клику на затемнённый фон и клавише `Esc`;
- сохранение штатной логики принятия пользовательского соглашения Bitrix.

## Структура

```text
form/
└── write_to_us/
    └── bitrix/
        └── form.result.new/
            └── .default/
                ├── template.php
                └── style.css

main.userconsent.request/
└── ic-consent/
    ├── template.php
    ├── component_epilog.php
    ├── user_consent.css
    ├── user_consent.js
    ├── user_consent.map.js
    ├── user_consent.min.css
    └── user_consent.min.js
```

`write_to_us` и `ic-consent` являются двумя отдельными шаблонами компонентов.

Шаблон `ic-consent` не нужно копировать внутрь каждого шаблона формы. Его можно использовать повторно в разных формах сайта.

## Установка

Скопировать папку:

```text
form/write_to_us
```

в:

```text
/local/templates/ИМЯ_ШАБЛОНА/components/bitrix/form/
```

В результате:

```text
/local/templates/ИМЯ_ШАБЛОНА/components/bitrix/form/write_to_us/
```

Отдельно скопировать:

```text
main.userconsent.request/ic-consent
```

в:

```text
/local/templates/ИМЯ_ШАБЛОНА/components/bitrix/main.userconsent.request/
```

В результате:

```text
/local/templates/ИМЯ_ШАБЛОНА/components/bitrix/main.userconsent.request/ic-consent/
```

## Настройка пользовательского соглашения

В начале `template.php` задаётся ID соглашения:

```php
$consentAgreementId = 1;
```

При необходимости заменить `1` на ID соглашения, созданного на конкретном сайте.

Также задаются поля, которые Bitrix подставляет в текст соглашения:

```php
$consentFields = [
    "Имя",
    "Телефон",
    "Email",
];
```

Этот массив необходимо изменить в соответствии с полями конкретной формы.

Компонент соглашения вызывается следующим образом:

```php
$APPLICATION->IncludeComponent(
    "bitrix:main.userconsent.request",
    "ic-consent",
    [
        "ID" => $consentAgreementId,
        "AUTO_SAVE" => "Y",
        "IS_LOADED" => "N",
        "IS_CHECKED" => "N",
        "REPLACE" => [
            "button_caption" => $arResult["arForm"]["BUTTON"],
            "fields" => $consentFields,
        ],
    ]
);
```

Название кнопки формы для текста соглашения берётся из:

```php
$arResult["arForm"]["BUTTON"]
```

Это позволяет использовать реальное название кнопки, заданное в настройках веб-формы Bitrix.

## ID полей

Шаблон проверяет, сформировал ли Bitrix собственный `id` для поля.

Если `id` уже существует, он сохраняется и используется для связи поля с `label`.

Если `id` отсутствует, шаблон создаёт его самостоятельно:

```text
prop_FIELD_SID
```

Например:

```text
prop_email
prop_name
prop_phone
```

Это позволяет избежать появления двух атрибутов `id` у одного элемента.

## Floating label

Floating label используется для обычных текстовых `input` и `textarea`.

При фокусе или заполнении поля `label` перемещается вверх.

Шаблон специально предназначен для форм с такими типами полей. Для универсальных форм, содержащих `select`, radio, группы checkbox, загрузку файлов и другие типы полей, рекомендуется использовать отдельный шаблон без floating label.

## Ошибки формы

Шаблон использует стандартную серверную валидацию Bitrix.

Общее сообщение об ошибках выводится через:

```php
$arResult["FORM_ERRORS_TEXT"]
```

и оформляется классом:

```text
.ic-form__errors
```

Размер текста ошибок уменьшен относительно стандартного оформления Bitrix, чтобы сообщение соответствовало общей типографике формы.

## Пользовательское соглашение

Для соглашения используется отдельный шаблон:

```text
bitrix:main.userconsent.request
```

с именем:

```text
ic-consent
```

Штатная логика Bitrix сохранена.

При первом клике на checkbox открывается окно с текстом соглашения. Checkbox устанавливается только после нажатия кнопки **«Принимаю»**.

Кнопка **«Не принимаю»** закрывает окно и оставляет checkbox неотмеченным.

Дополнительно реализовано закрытие окна:

- по крестику;
- кликом на затемнённый фон;
- клавишей `Esc`.

При таком закрытии пользователь не считается принявшим или отклонившим соглашение — checkbox остаётся неотмеченным.

## Checkbox соглашения

Стандартный внешний вид checkbox заменён собственным CSS-оформлением.

Предусмотрены состояния:

- обычное;
- `focus`;
- `focus-visible`;
- `checked`.

При навигации клавишей `Tab` фокус отображается изменением цвета рамки checkbox.

Для предотвращения конфликта со стандартными стилями Bootstrap используется более специфичный селектор:

```css
input.ic-consent__checkbox[type="checkbox"]:focus
```

## Важно о CSS формы

Не следует использовать глобальное правило:

```css
.ic-form input {
    border: none;
}
```

Оно воздействует в том числе на checkbox пользовательского соглашения.

Для обычных полей используется более точный селектор:

```css
.ic-form__field input {
    height: 48px;
    border: none;
}
```

Таким образом стили текстовых полей не вмешиваются в оформление checkbox.

## Сообщение об успешной отправке

Текст успешной отправки веб-формы Bitrix приходит в:

```php
$arResult["FORM_NOTE"]
```

Не рекомендуется изменять файлы системного компонента в:

```text
/bitrix/components/bitrix/
```

Для изменения текста следует использовать настройки/переопределение сообщения либо обрабатывать вывод сообщения в собственном шаблоне компонента.

Если сообщение выводится самостоятельно на основании `FORM_NOTE`, обязательно нужно проверять успешное состояние формы, иначе сообщение может отображаться ещё до отправки.

## Ограничения

Шаблон `write_to_us` рассчитан прежде всего на компактные формы с текстовыми полями и `textarea`.

Он не предназначен как универсальный шаблон для всех возможных типов полей Bitrix.

Для форм с:

- `select`;
- radio;
- группами checkbox;
- загрузкой файлов;
- множественными значениями;
- другими сложными типами полей

рекомендуется использовать отдельный универсальный шаблон без floating label.

## Примечание

Файлы системных компонентов Bitrix в:

```text
/bitrix/components/bitrix/
```

изменять не следует.

Все изменения выполняются в собственных шаблонах компонентов сайта. Это позволяет обновлять 1С-Битрикс без потери внесённых изменений.
